Identificati i seguenti problemi con il metodo attuale di estrazione semantica dei dati.

1. Generic token extraction: The regex patterns in extract_generic_code() and extract_document() create entities from common words like "the", "to", "_" without proper filtering
2. No provenance tracking: Entities don't have proper links back to exact source chunks
3. Lossy extraction: The script doesn't preserve full file content or create a complete file inventory
4. Weak entity resolution: The resolve_relation_endpoints() function uses name-based matching which causes ambiguity
5. No file-level completeness: Binary files, config files, and many document types aren't properly inventoried
6. Regex-based extraction: Heavy reliance on regex instead of proper parsers for supported languages
7. Missing source chunks: No mechanism to preserve exact text excerpts for evidence
8. Confidence on nodes: The prompt says confidence should be on relationships, but the script puts it on entities too 

Criticità strutturali nello script che spiegano i problemi nell'output:

1. Estrazione Basata su Regex Non Filtrate (Criticità Maggiore)
```python
# Nel codice attuale - PROBLEMA
for match in re.finditer(r"(?i)\b(?:api|endpoint|interface|function)\s*[:`]*\s*([A-Za-z_]\w*)", text):
    name = match.group(1)  # Cattura ANY parola, incluso "_", "the", "to"
```
Conseguenza: Genera entità semantiche da token generici senza validazione del contesto.

2. Assenza di Source Chunking
Lo script non crea nodi SourceChunk che preservino il testo esatto. Le entità semantiche puntano solo a file + line_number, ma non c'è modo di recuperare l'evidenza testuale per validazione downstream.

3. Entity Resolution Debole
```python
# Nel codice attuale - PROBLEMA
nodes_by_name[entity.name.casefold()].append(entity)  # Lookup solo per nome
``` 
Conseguenza: Nomi generici ("config", "handler") causano moltiplicazione cartesiane nelle relazioni.

4. File Inventory Incompleto
Lo script processa solo file con estensioni pre-definite. File binari, config non standard, e documentazione in formati non elencati sono ignorati.

5. Provenance non Tracciata
Le relazioni non hanno proprietà source_chunk_uid o evidence_text. Non c'è modo per un agent downstream di verificare se una relazione (:Function)-[:CALLS]->(:Function) è esplicita o inferita.

6. Confidence Misplaced
Il prompt specifica che il confidence score è proprietà della relazione, ma lo script assegna confidence anche alle entità (entity.confidence), creando ambiguità semantica.
