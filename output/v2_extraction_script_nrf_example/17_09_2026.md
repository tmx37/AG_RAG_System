# Audit: perche' v2 (nRF, regex-first) viene archiviata e sostituita da v3

Questa cartella congela lo stato "v2" della pipeline: prompt di estrazione,
script, schema e dati generati sul corpus `raw_data/sdk-nrf` (nRF Connect SDK).
E' la base dati usata per rispondere a domande reali su Bluetooth/Bluetooth
Mesh durante il bring-up di un nRF54L15. L'esito di quel test e' stato
negativo: il grafo non ha fornito informazioni utilizzabili in produzione
(vedi conversazione "Connect to Memgraph DB and analyze").

## Causa radice confermata leggendo `output/extraction_script.py` (v2)

1. **`extract_document()` non usa un parser.** Il regex
   `\b(?:api|endpoint|interface|function)\s*[:\`]*\s*([A-Za-z_]\w*)` cattura
   la prima parola dopo "API"/"interface"/"function" in qualunque frase di
   prosa RST, producendo nodi `:API`/`:Concept` come `Device`, `Guidelines`,
   `ABC`, `Due`, `Handler`, `Event`: parole inglesi comuni, non simboli reali.
2. **`extract_generic_code()` non usa un parser per C/C++.** Le funzioni e le
   struct sono regex su testo grezzo (commenti e stringhe inclusi), quindi
   comment/prosa dentro i file `.c/.h` possono generare falsi simboli.
3. **`level_three()` fa cross-linking per nome, senza scoping.** Il matching
   `nodes_by_name[entity.name.casefold()]` collega qualunque parola di un
   documento a qualunque simbolo di codice con lo stesso nome in tutta la
   repository, creando relazioni `REFERENCES`/`SATISFIES` fasulle (es. la
   parola "device" in un README collegata a uno struct `device` in un board
   file scorrelato).
4. **Nessun parser per Kconfig o Devicetree.** Per un SDK firmware, le opzioni
   Kconfig (`CONFIG_BT_MESH`, `CONFIG_...`) e i nodi Devicetree (`hfxo:`,
   `compatible = "..."`) sono la superficie di implementazione piu'
   rilevante per il bring-up. v2 li tratta come testo generico: zero
   nodi/relazioni dedicati. E' la ragione diretta per cui l'agente non ha
   trovato nulla di verificabile sulla capacita' di carico dell'HFXO.
5. **`Requirement` troppo permissivo.** Il gruppo `(?:shall|must|should)?` e'
   opzionale nel regex, quindi frasi senza alcun verbo modale (es. "API
   allows you to...") sono state estratte come `:Requirement`.
6. **Confidence sulle entita', non solo sulle relazioni** (gia' annotato in
   `logs/16-09-2026.md`, mai risolto in v2).

## Decisione

Sostituire l'estrazione regex/euristica con parser reali via
`tree-sitter-language-pack` (grammatiche precompilate, nessuna necessita' di
preprocessore C): `c`, `cpp`, `kconfig`, `devicetree`, `rst`, `yaml`, oltre al
modulo nativo `ast` di Python gia' in uso. Verificato sul corpus reale in
questa sessione (vedi `agents/rules/prompt_knowledge_graph_extraction.md` v3
e `output/extraction_script.py` v3) che questi parser estraggono
correttamente, ad esempio, il nodo Devicetree `hfxo` con
`compatible = "nordic,nrf54l-hfxo"` e l'opzione Kconfig `BT_MESH` con le sue
`depends on`/`select` reali: dati che v2 non modellava affatto.

Aggiunta inoltre la componente mancante richiesta esplicitamente
dall'utente: un aggiornamento incrementale basato su hash dei file
(`output/ingestion_manifest.json`), cosi' che ri-ingerire dopo una modifica
al `raw_data/` tocchi solo i file cambiati invece di richiedere un reload
completo del grafo.
