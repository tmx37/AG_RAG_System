# AG_RAG_System: Evidence-Backed Graph-RAG Knowledge Base for code intelligence and other AI applications

This repository is an implementation of techniques for building a Graph based on a real dataset composed of files of various types, such as code and/or documentation.

## To run
Remember to enter `.venv` environment for python imports.
```bash
    # windows
    ./.venv/Scripts/Activate.ps1
    
    # linux
    source .venv/bin/activate
```
**Index**:
- `./DB`..........................: docker-compose.yml for MemGraphDB container
- `./doc`.........................: documentation folder based on .md 
- `./agents`......................: agent-related prompts, rules and tools
    - `../rules`..................: prompts for ai agents
- `./logs`........................: dev and agentic logs
- `./output`......................: agentic output
    - `../extraction_script.py`...: this script performs the whole `./raw_data/` dataset ingestion into running memgraph. This could be generated by executing the `prompt_knowledge_graph_extraction.md` present in `./agents/rules`.

### Pre-Requisites
- Docker
- Python 3.0
- doxygen
- Install requests in venv: `python -m pip install requests`
- Install requirements: `pip install -r requirements.txt`

## Primary Denomination
**Provenance-Aware Knowledge Graph Construction for Code Intelligence**
The approach consists of:
| Component | Reference Discipline |
|------------|--------------------------|
| Knowledge Graph Construction | Knowledge Representation & Reasoning (KR&R) |
| Provenance-Aware | Data Provenance / Scientific Workflow Management |
| Code Intelligence | Program Analysis / Software Engineering |
| Evidence-Backed Extraction | Information Extraction (IE) |

## Specific Methodologies Implemented
### 1. **Static Program Analysis**
Structural extraction from source code without execution falls within this established discipline. Specifically:
- **AST-based extraction**: Parse tree traversal to identify declarations
- **Control Flow Analysis**: Tracking calls and dependencies
- **Data Flow Analysis**: Tracking variables and scope

### 2. **Information Extraction (IE) Pipeline**
```
Document → Tokenization → Entity Recognition → Relation Extraction → Knowledge Base
```
With the critical addition of the **provenance layer** which is not always present in traditional IE systems.

### 3. **Provenance-Aware Data Management**
The project proposes systematic tracking of:
- **Origin Provenance**: Which file/chunk each entity comes from
- **Derivation Provenance**: How each relation was inferred
- **Confidence Provenance**: Why a certain confidence score was assigned
In literature, this approach is called **"Evidence-Backed Knowledge Graph"** or **"Auditable Knowledge Graph"**.
```
┌────────────────────────────────────────────────────────────┐
│  Provenance-Aware Code Knowledge Graph      │
├────────────────────────────────────────────────────────────┤
│  ✓ File-level completeness (100% inventory)                │
│  ✓ Deterministic chunking with evidence preservation        │
│  ✓ AST-first extraction (parser > regex)                   │
│  ✓ Mandatory provenance per entity/relation                │
│  ✓ Confidence scoring on relations (not nodes)              │
│  ✓ Rigorous entity resolution (discard ambiguous)             │
│  ✓ Post-ingestion verification with fail on errors          │
└───────────────────────────────────────────────────────────┘
```

### 4. **Multi-Layer Graph Architecture**
The layered structure (File → Chunk → Entity → Relation) implements a pattern known as:
- **Physical Layer**: File system inventory
- **Logical Layer**: Source chunks
- **Semantic Layer**: Typed entities
- **Inferential Layer**: Extracted relations
This architecture is documented in systems such as **Amazon Neptune ML** and **Neo4j Knowledge Graph pipelines**.

### 5. **RAG Infrastructure Pattern** (Retrieval-Augmented Generation)
The output graph could be classified as a **knowledge base for downstream agents**, which involves:
- **Graph-RAG**: Retrieval based on graph traversal instead of vector similarity
- **Hybrid Retrieval**: Combination of structured lookup (graph) + full-text (chunks)

This specific combination is emerging in 2024-2025 with the adoption of **Graph-RAG** for enterprise AI applications. It does not yet have a single standardized denomination, but the most accurate description could be: "Evidence-Backed Graph-RAG Knowledge Base for Code Intelligence"
